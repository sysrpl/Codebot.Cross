The codebot_webkit package provides a web browser as an LCL control. On Linux it embeds WebKitGTK, which is built for GTK3, and on Windows it embeds Microsoft Edge WebView2. The package builds with the GTK3 and Win32 widgetsets. The package requires codebot_controls and the LCL.

## Browser

Codebot.WebKit.Controls defines TWebBrowser, which is a control that shows web pages. It can do the following:

- Load a location or a string of HTML.
- Stop and reload a page.
- Go back and forward in its history.
- Run JavaScript.
- Zoom, and make the page editable.

Its events report the location, title, progress, and status of a page as it loads, as well as errors, what is under the mouse, context menus, and the alert, confirm, and prompt dialogs of JavaScript. An event can also allow or deny a navigation. Files that the browser downloads are TWebDownload objects, and TWebInspector is a control that shows the developer tools of a browser.

## Extras

Codebot.WebKit.Controls.Extras defines controls that work alongside a browser. TWebAddressBar has an edit that shows the current location and buttons for back, forward, home, refresh, history, the inspector, print, capture, downloads, and settings. TWebStatusIndicator shows the status of a browser.

## Other units

| Unit | Description |
| --- | --- |
| Codebot.WebKit.Controls.Gtk3 | The GTK3 widgetset classes, which create the web view and the inspector and pass their signals on to the controls. |
| Codebot.Interop.WebKit | The part of the WebKitGTK C API that the package uses. |
| Codebot.WebKit.Controls.Win | The Win32 widgetset classes, which create a WebView2 web view and pass its events on to the controls. |
| Codebot.Interop.WebView2 | The part of the WebView2 API that the package uses. |

The web view library is loaded when InitWebKit is called, rather than being linked when the program is built. This allows a program to start normally and report that the library is not installed. The controls have no web view at design time, or when the library is missing.

## Windows

On Windows a program using the browser needs WebView2Loader.dll next to it. A copy is in the win64 folder of this package. The WebView2 runtime itself is part of Windows 11 and is installed on nearly all Windows 10 systems.

Some features differ on Windows. Only one step back or forward in history is possible, HistoryItem returns false, ZoomTextOnly has no effect, and the progress of a load advances in steps. TWebInspector shows the developer tools page served by the WebView2 debugging server, which listens only on the local computer and is started only when a TWebInspector is created before the first web view. Without one, the developer tools open in a window of their own.
